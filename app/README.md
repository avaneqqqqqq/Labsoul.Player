# Обёртка Яндекс.Музыки: тема + кастомизация

Каркас Electron-приложения: музыка открывается как обычно (официальный веб-клиент), а оформление, блоки и эквалайзер живут в отдельном окне «Оформление».

## Запуск

Самый простой способ — двойной клик по **`start.cmd`**: он сам поставит зависимости, если их нет, и запустит приложение.

Или из терминала:

```powershell
cd app
npm.cmd install      # если ещё не ставили (скачает electron ~120 МБ)
npm.cmd start
```

Горячие клавиши: **Ctrl+E** — оформление, **Ctrl+Shift+E** — эквалайзер, **Esc** в окне оформления — закрыть.

### Если приложение падает сразу, без окна

Почти всегда причина — переменная окружения `ELECTRON_RUN_AS_NODE=1` (её выставляют некоторые IDE, оболочки и агенты): тогда `electron.exe` стартует как обычный Node и падает на `require('electron')`.

Обход уже встроен: `start.cmd` очищает переменную, а `npm start` идёт через `launch.cjs`, который делает то же самое. Поэтому запускайте именно `start.cmd` или `npm start`, а не `electron .` напрямую.

```powershell
$env:ELECTRON_RUN_AS_NODE        # если выводит 1 — это как раз тот случай
```

## Раздать друзьям

Собрать установщик:

```powershell
cd app
npm.cmd run dist
```

Или двойной клик по **`build.cmd`** — он сам выставит `TEMP` и кеши, поставит зависимости и пересоберёт установщик.

На выходе в `app/dist/`:

| Файл | Что это |
|---|---|
| `TemnikovoDans-0.2.0-setup.exe` | установщик (NSIS): ярлык, папка установки, удаление через «Приложения» |
| `latest.yml` | манифест автообновления (версия, sha512, имя файла) |
| `TemnikovoDans-0.2.0-setup.exe.blockmap` | карта блоков для дифференциальных обновлений |

Портативной сборки сознательно нет: она не умеет обновлять сама себя, и половина друзей осталась бы на старой версии. Другу нужен один файл — установщик: скачал → запустил → вошёл в свой аккаунт. Node, npm и терминал не нужны.

Что важно знать при раздаче:

- **SmartScreen будет ругаться.** Установщик не подписан (сертификат стоит денег), Windows покажет «Неизвестный издатель» → «Подробнее» → «Выполнить в любом случае». Без подписи это неизбежно. Как это чинится — в [SIGNING.md](SIGNING.md).
- **Аккаунт у каждого свой.** Сессия хранится в `%APPDATA%\Temnikovo Dans`, вход выполняется на странице Яндекса. Никаких общих токенов и паролей приложение не передаёт.
- **Подписка** работает только та, что есть у пользователя: приложение не разблокирует Plus и не обходит ограничения.
- **Обновления** — автоматические, см. раздел «Автообновление».
- **Имя** специально не содержит «Яндекс»: это сторонняя обёртка, а не официальный клиент.

### Правовая рамка — прочитай перед раздачей

Обёртка меняет внешний вид и поведение чужого интерфейса, а это прямо запрещено пользовательским соглашением Яндекса. Персональное использование — серая зона с риском для аккаунта; **публичное распространение** (в том числе «для друзей») повышает этот риск: возможны жалобы правообладателя и блокировка аккаунтов у тех, кто пользуется.

Что снижает риск:

- никаких обходов подписки, DRM и скачивания стриминга;
- никакого использования товарных знаков в названии и иконке;
- никакой монетизации;
- честное описание в README, что это неофициальный клиент.

Если планируешь раздавать широко — разумнее сперва спросить у Яндекса разрешение или сделать приложение-обёртку без модификации их интерфейса (только свои окна и тема).

### Автообновление

Установленная версия сама проверяет обновления: через 8 секунд после запуска, в фоне, и предлагает «Перезапустить», когда новая версия скачана. Вручную — меню «Проверить обновления…».

Как включить:

1. Открой `app/update.json` и впиши `"url"` — адрес папки, где будут лежать файлы обновлений (обязательно **HTTPS**).
2. Пересобери приложение (`build.cmd`).
3. Залей в эту папку **три файла** из `dist/`:

```
TemnikovoDans-0.2.0-setup.exe
TemnikovoDans-0.2.0-setup.exe.blockmap
latest.yml
```

`latest.yml` — это манифест: версия, имя файла, sha512, размер. Приложение скачивает его первым и решает, нужно ли обновляться.

Выпуск новой версии:

```powershell
# 1. поднять версию
npm version patch --no-git-tag-version
# 2. пересобрать
build.cmd
# 3. залить три файла с новыми именами в ту же папку
```

Ограничения, о которых надо помнить:

- **HTTPS обязателен** — кроме `localhost`, electron-updater по http откажется.
- **SmartScreen будет ругаться на каждый новый exe**, пока нет сертификата: подпись не настроена, а каждый релиз — новый файл.
- Если `"url"` пустой, автообновление молча выключено — приложение работает как обычно.

Вместо своей папки можно раздавать через GitHub Releases: в `package.json` → `build.publish` поставь `{"provider": "github", "owner": "твой-логин", "repo": "temnikovo-dans"}` и собирай с `--publish always` (нужен `GH_TOKEN`). Тогда файл `update.json` не нужен — адрес берётся из ресурсов сборки.

### Если сборка падает

Три грабли, на которых я уже спотыкался (все обойдены в конфиге):

- **`winCodeSign`: «Cannot create symbolic link»** — внутри архива macOS-симлинки, Windows без прав их не создаёт. Обход: `"signAndEditExecutable": false` в `build.win`. Побочный эффект: иконка не вшивается в свойства `.exe` (в свойствах файла будет иконка Electron), но в окне и на панели задач — наша.
- **NSIS: «Unable to create temporary file»** — сборщику нужен доступный `TEMP`. Запускай, задав `$env:TEMP` внутри проекта.
- **`readObjectStart: expect { or n`** — `package.json` сохранён с BOM. Пересохрани без BOM.

## Как это устроено

```
app/
  main.js            главный процесс: окно музыки + окно оформления + IPC
  theme.js           JSON темы → CSS-переменные и скрипт блоков
  preload-editor.js  мост: читает тему из localStorage прототипа и отдаёт в main
  blocks.json        якоря блоков Яндекс.Музыки (заполняется по devtools)
  patches.css        L3-правки их DOM (по умолчанию пусто, с примерами)
  ../yandex-music-redesign/   сам прототип: сетка, 4 стиля, эквалайзер
```

Поток:

1. Окно оформления открывает `yandex-music-redesign/index.html?page=theme&embed=1` — это тот же прототип, но без сайдбара и плеера.
2. Любое изменение в нём сохраняется в `localStorage`, `preload-editor.js` читает его дважды в секунду и отправляет в главный процесс.
3. Главный процесс собирает CSS из токенов (`theme.js`) и вставляет его в окно музыки через `webContents.insertCSS(..., { cssOrigin: 'user' })`.
4. Тема пишется в `%APPDATA%/Temnikovo Dans/theme.json` и поднимается при старте.

Подписка и аккаунт — свои: окно музыки использует отдельный профиль `persist:ym-main`, вход выполняется на странице Яндекса. Приложение ничего не разблокирует и не хранит пароль.

## Что уже работает

- окно музыки с изолированной сессией;
- окно оформления, связанное с музыкой в реальном времени;
- сохранение темы в файл и восстановление при запуске;
- инъекция токенов (`--ym-*`) в страницу;
- скрытие блоков по якорям из `blocks.json` в safe mode: не нашёл — не скрыл, вернул отчёт;
- меню, горячие клавиши, сброс темы.

## Что требует калибровки

Токены применяются всегда, а **правки их интерфейса** — только после того, как в `blocks.json` появятся настоящие селекторы. Порядок:

1. Запустить `npm start`, войти в аккаунт.
2. Ctrl+Shift+I — DevTools, найти нужный блок.
3. Взять устойчивый якорь: `role`, `data-*`, `aria-label`, текст. Не класс с хешем.
4. Записать в `blocks.json` → перезапустить. Если блок не найден, он просто не скроется.

Отчёт о применении пишется в консоль главного процесса и в `window.__ymBlocksReport` окна оформления.

## Эквалайзер: честно

Экран эквалайзера — полноценный UI (10 полос, 9 пресетов, предусиление, сохранение в тему). Но **обработать звук Яндекс.Музыки из обёртки нельзя**: аудио идёт через их плеер в веб-вью, а перехватить чужой медиапоток из другого origin невозможно.

Работающие варианты:
- применять эквалайзер к **своему** аудио-слою (виджет SoundCloud, локальные файлы) через Web Audio API;
- экспортировать пресет в системный эквалайзер (Equalizer APO / Peace на Windows) — это влияет на всё приложение сразу.

Экспорт пресета пока не реализован — следующий шаг.

## Ограничения и правовая рамка

- приложение не обходит подписку, DRM и не скачивает чужой стриминг;
- модификация интерфейса формально противоречит пользовательскому соглашению Яндекса — это персональный инструмент, не продукт для распространения;
- при обновлениях сайта правки из `patches.css` могут отваливаться: тема — нет, DOM-правки — да.
