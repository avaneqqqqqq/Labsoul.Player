# Как подключить автообновление

Код уже готов: приложение раз в запуск читает `update.json`, качает манифест `latest.yml` и, если версия новее, скачивает установщик и предлагает перезапуститься.

Не хватает одного — **адреса, откуда это качать**. Ниже три способа, от простого к «правильному».

## Что именно нужно выложить

Из `dist/` — всегда три файла, в одну папку:

```
latest.yml
TemnikovoDans-0.2.1-setup.exe
TemnikovoDans-0.2.1-setup.exe.blockmap
```

Имена не переименовывать: `latest.yml` ссылается на exe по имени, а обновлятор скачивает ровно это имя.

## Способ 1. Netlify Drop / Cloudflare Pages — 5 минут

1. Собери новую версию: `npm version patch --no-git-tag-version` → `build.cmd`.
2. Открой https://app.netlify.com/drop (или дашборд Cloudflare Pages → Direct Upload).
3. Перетащи папку `dist` целиком.
4. Получишь HTTPS-адрес вида `https://random-name-123.netlify.app/`.
5. Впиши его в `update.json` → `"url"` и пересобери приложение — **это станет точкой входа для всех будущих обновлений**.

Плюсы: без регистрации домена, HTTPS из коробки, файлы раздаются напрямую. Минусы: адрес некрасивый, при пересоздании сайта меняется — а URL зашит в `update.json` у друзей, так что лучше сразу сделать стабильный домен или не удалять сайт.

## Способ 2. GitHub Releases — бесплатно и надёжно

Сейчас в проекте настроен именно этот вариант: `build.publish` → `github`, а в корне лежит workflow `.github/workflows/release.yml`.

### Что уже сделано за тебя

- `app/package.json` → `build.publish` = `github` (owner-заглушка, в CI подставляется автоматически);
- `.github/workflows/release.yml` — при пуше тега `v*` собирает установщик и прикрепляет его к релизу (Windows-runner, `npm ci`, `npm test`, `electron-builder --publish always`);
- `.gitignore` — `node_modules`, `dist`, кеши сборки и скриншоты не попадают в репозиторий;
- приложение теперь само берёт адрес из `app-update.yml` внутри сборки. `update.json` можно оставить пустым — он нужен только для своего (generic) фида.

### Что нужно сделать (без git, всё через сайт)

1. Создай репозиторий на github.com → **Public** (важно: приватный требует токен у каждого друга).
2. Загрузи проект: **Add file → Upload files**, перетащи содержимое папки `yandex-music-redesign` (вместе с `.github`). `node_modules` и `dist` загружать не надо — их нет в `.gitignore`, но лучше не тащить 300 МБ.
3. Проверь, что в репозитории виден `.github/workflows/release.yml`.
4. Создай релиз: **Releases → Draft a new release** → тег `v0.2.0` → Publish.
5. Пуш тега запустит Actions: соберётся установщик и прикрепится к релизу. Через 3–5 минут в Releases появится `TemnikovoDans-0.2.0-setup.exe` + `latest.yml`.
6. Ссылка для друзей — страница релиза.

Новая версия: поднимаешь версию в `app/package.json` (или `npm version patch` локально), коммитишь, создаёшь релиз с тегом `v0.2.1` — Actions соберёт и опубликует сам. Установленные приложения подхватят обновление в фоне.

### Если хочешь собирать локально с gh

```powershell
winget install Git.Git GitHub.cli
gh auth login
$env:GH_TOKEN = (gh auth token)
npm run dist -- --publish always
```

Плюсы GitHub: история версий, бесплатно, файлы не пропадут, автоматизация через Actions. Минусы: репозиторий публичный (значит, публичен и код, и факт существования приложения — для правовой рамки это стоит учитывать).

## Способ 3. Свой сервер / VPS

Любой статический хостинг с HTTPS: nginx, Caddy, S3-совместимое хранилище. Папка `https://твой-домен/updates/` с теми же тремя файлами. В `update.json` — этот адрес.

Важно: **HTTPS обязателен**, кроме `localhost`. По http electron-updater откажется.

## Как проверить, что всё работает

Локально, без интернета и без друзей:

```powershell
# 1. собери текущую версию и поставь её (или запусти из dist\win-unpacked для теста)
# 2. подними локальную раздачу
node serve-feed.cjs 8080
# 3. в update.json установленного приложения укажи url: http://localhost:8080/
# 4. подними версию, пересобери, положи новые файлы в dist
# 5. запусти приложение — через 8 секунд в консоли появится [update] новая версия: 0.2.1
```

Логи обновления пишутся в консоль приложения (`[update] ...`). Если запускать из `dist\win-unpacked\Temnikovo Dans.exe` через терминал — увидишь их сразу.

## Частые грабли

- **`latest.yml` не обновился.** Он пересоздаётся при каждой сборке, но если заливаешь вручную — легко забыть. Проверяй, что внутри `version:` новая.
- **Скачалось, но не ставится.** Установщик должен лежать рядом с манифестом; блокмап нужен для дифференциального обновления, без него скачается полный файл.
- **`ERR_UPDATER_INVALID_SIGNATURE`.** Появится, если включишь подпись, но не добавишь `publisherName` в `build.win` — обновлятор сверяет издателя.
- **Портативной сборки нет** — и это к лучшему: она не умеет обновляться, и часть друзей застряла бы на первой версии.
