# Подпись приложения (code signing)

Коротко: **без сертификата подписать нельзя.** Подпись — это криптографический отпечаток, выданный удостоверяющим центром после проверки личности/организации. Самоподписанный сертификат технически ставит подпись, но SmartScreen всё равно показывает «Неизвестный издатель»: Windows не доверяет такому корню.

И отдельно: подпись защищает от «неизвестного издателя» в Windows, но никак не решает вопрос с правообладателем — это разные плоскости.

## Варианты

| Вариант | Цена (ориентир) | Что даёт | Сложность |
|---|---|---|---|
| Без подписи (сейчас) | 0 | SmartScreen ругается на каждом новом файле | — |
| Самоподписанный | 0 | Подпись есть, доверия нет; годится только для себя | 10 минут |
| OV-сертификат | ~15–40 тыс ₽/год | Подпись валидна; репутация SmartScreen набирается по мере скачиваний (недели) | средняя |
| EV-сертификат | ~30–70 тыс ₽/год | Мгновенная репутация SmartScreen | высокая |
| Azure Trusted Signing | ~$10/мес | Облачная подпись без токена | средняя: Azure + верификация |
| Certum Open Source | ~€25/год | Дёшево, но только для публичного open-source репо | низкая, но проект открытым быть не может |

С 2023 года OV/EV для Windows выдают **только на аппаратном токене или в облачном HSM** — обычный `.pfx` больше не выдают. Это важно: подпись «файлом на диске» больше не купить, нужен физический токен либо облачный сервис (Azure Trusted Signing, DigiCert KeyLocker, SSL.com eSigner).

Полезная деталь: с 2024–2025 у Certum/CustomID есть варианты для ИП и самозанятых, но верификация личности всё равно обязательна. Иностранные УЦ принимают российские паспортные данные не всегда — проверяй до оплаты.

## Как включить, когда сертификат появится

### Вариант A — токен/PFX + electron-builder

1. Включи **режим разработчика** Windows (Параметры → Система → Для разработчиков). Без него сборка падает на распаковке `winCodeSign`: внутри архива macOS-симлинки, а Windows без прав их не создаёт.
2. В `package.json` верни `"signAndEditExecutable": true` (сейчас стоит `false` — это компромисс, чтобы сборка шла без токена).
3. Задай переменные и собери:

```cmd
set CSC_LINK=C:\path\cert.pfx
set CSC_KEY_PASSWORD=пароль
npm run dist
```

Для аппаратного токена вместо `CSC_LINK` указывают отпечаток сертификата (`CSC_NAME` или `--config.win.certificateSubjectName`), а подпись идёт через `signtool` с токеном.

4. Проверь:

```cmd
signtool verify /pa dist\TemnikovoDans-0.2.0-setup.exe
```

### Вариант B — Azure Trusted Signing

Облачная подпись без токена. В electron-builder 25 настраивается через `win.azureSignOptions`:

```json
"win": {
  "azureSignOptions": {
    "publisherName": "Твоё ИП/ООО",
    "endpoint": "https://weu.codesigning.azure.net",
    "codeSigningAccountName": "account-name",
    "certificateProfileName": "profile-name"
  }
}
```

Нужны: подписка Azure, верифицированный аккаунт, регион из списка поддерживаемых. Для физлица доступность зависит от страны — проверять в документации Microsoft.

### Вариант C — подписать после сборки

Собрать без подписи, потом подписать `setup.exe` вручную `signtool` из Windows SDK. Годится, если сертификат уже на токене и не хочется трогать сборку.

Замечание: установщик подписывается даже при `signAndEditExecutable: false` — этот флаг относится к exe самого приложения. То есть для «убрать предупреждение у установщика» достаточно `CSC_LINK` + `CSC_KEY_PASSWORD`, а включать `true` нужно только чтобы подписать/отредактировать исполняемый файл внутри.

## Что не забыть при включении подписи

- **`publisherName`.** Если подпись включена, добавь в `build.win` поле `"publisherName"` с точным именем из сертификата. Electron-updater сверяет его при обновлении и без совпадения может отвергнуть апдейт.
- **Подписывать надо каждый релиз**: установщик, uninstaller (electron-builder делает это сам при подписи), а для автообновления — `latest.yml` пересобирается с новыми хешами.
- **SmartScreen и OV**: даже с валидной подписью предупреждение может появляться, пока файл новый и мало скачиваний. EV и Trusted Signing дают репутацию сразу.

## Что подпись не решает

- жалобы правообладателя на модификацию интерфейса — вопрос лицензии, а не подписи;
- доверие антивирусов к «модифицирующим» приложениям;
- необходимость честно писать в README, что это неофициальный клиент.
