# Оформление Яндекс Музыки: как это внедряется в реальное приложение

Документ описывает, как прототип (`index.html`) превращается в рабочий слой темы поверх десктопного клиента, а не остаётся макетом. Речь про вариант **B** — обёртка вокруг веб-версии, а не патч APK и не полностью свой плеер.

---

## 1. Архитектура

```
┌──────────────────────────────────────────────┐
│ Electron-обёртка (наше приложение)           │
│                                              │
│  chrome: свой топбар, сайдбар, вкладки       │
│  ┌────────────────────────────────────────┐  │
│  │ <webview>  https://music.yandex.ru     │  │
│  │  + insertCSS(theme)                    │  │
│  │  + executeJavaScript(hooks)            │  │
│  └────────────────────────────────────────┘  │
│  слой данных: импорт, SoundCloud, темы       │
└──────────────────────────────────────────────┘
```

Ключевое решение: **не патчим `app.asar` официального клиента**. Официальный клиент — это тоже Electron-обёртка над `music.yandex.ru` (как и `yandex-music-desktop`), поэтому:

- не ломаемся при автообновлении Яндекс.Музыки;
- не трогаем подписи и не воюем с антивирусом;
- пользователь может в любой момент запустить официальный клиент рядом.

Альтернатива — форк самого официального Electron-приложения с подменой `app.asar/package.json` (так делают существующие патчеры). Плюс: сохраняется их оболочка и трей. Минус: каждое обновление — ручная пересборка. Для редизайна это плохой путь: наш UI всё равно перекрывает их.

---

## 2. Слои применения

Стили накладываются в три слоя, от безобидного к рискованному:

| Слой | Что делает | Риск |
|---|---|---|
| **L1. Токены** | `:root { --ym-accent: … }` + перекрытие существующих CSS-переменных Яндекс.Музыки, если они у них есть | нулевой |
| **L2. Компоновка** | наши собственные панели (обои, рельсы, шапка) внутри нашего chrome; веб-вью просто получает рамку | низкий |
| **L3. DOM-правки** | скрыть/переставить блоки их интерфейса, `!important` по селекторам | средний: ломается при релизах |

Правило: **новое рисуем сами, старое только прячем**. Любая попытка перекрасить их компоненты точечно — источник вечных поломок.

## 3. Токены

Один и тот же набор переменных используют и прототип, и обёртка.

| Токен | Тип | Значения |
|---|---|---|
| `--ym-scheme` | enum | `dark` / `light` / `amoled` |
| `--ym-variant` | enum | `glass` / `vinyl` / `neon` / `paper` |
| `--ym-accent` | color | любой; при `accentAuto` считается из обложки |
| `--ym-on-accent` | color | вычисляется по контрасту (L > 0.42 → тёмный текст) |
| `--ym-bg` / `--ym-bg-2` | color | фон окна и утопленных панелей |
| `--ym-panel` | color+alpha | стекло панелей |
| `--ym-text` / `--ym-dim` / `--ym-mute` | color | три уровня текста |
| `--ym-radius` | px | 0–34, слайдер |
| `--ym-blur` | px | 0–48, слайдер |
| `--ym-grain` | 0…1 | зерно |
| `--ym-density` | enum | `compact` / `normal` / `roomy` → меняет `--pad`, `--gap`, `--row-h` |
| `--ym-font` | enum | `ui` / `serif` / `mono` |
| `--ym-wallpaper` | string | имя пресета или inline-градиент |
| `--ym-cover-size` | enum | `s` / `m` / `l` |

Формат хранения — ровно тот JSON, который экспортирует прототип:

```json
{
  "variant": "glass",
  "scheme": "dark",
  "accent": "#ffd23f",
  "accentAuto": true,
  "wallpaper": "cover",
  "density": "normal",
  "radius": 22,
  "blur": 24,
  "grain": true,
  "anim": true,
  "font": "ui",
  "cards": "m"
}
```

Файл лежит в `%APPDATA%/<app>/themes/<name>.json`, активная тема — в `settings.json`. Прототип хранит то же самое в `localStorage` под ключом `ym-theme`.

## 4. Авто-палитра из обложки

Акцент «из обложки» — не магия, а четыре шага:

1. **Источник картинки.** Слушаем `navigator.mediaSession.metadata.artwork` или DOM плеера (у веб-версии есть `<img>` текущего трека). Fallback — ссылка обложки из API.
2. **Загрузка.** `fetch` картинки → `createImageBitmap` (не `<img>`, чтобы не терять на декодировании).
3. **Квантование.** Уменьшаем до 64×64 на `OffscreenCanvas`, считаем гистограмму в OKLCH, берём доминирующий кластер (median cut или MMCQ). Готовые реализации — `colorthief` / `vibrant.js`, но 60 строк своего кода дают больше контроля над «насыщенностью».
4. **Нормализация.** Приводим к рабочему диапазону: `L` 0.55–0.8, `C ≥ 0.12`, иначе акцент будет грязным или невидимым. Считаем `--ym-on-accent` по контрасту.

Дополнительно: из обложки можно брать не только акцент, но и пару для обоев — ровно это делает прототип в режиме «Из обложки».

## 5. Обои

| Режим | Реализация |
|---|---|
| Из обложки | те же цвета, что в п.4; `radial-gradient` + `linear-gradient` слои, поверх — затемняющая вуаль под текущую схему |
| Градиенты (Аврора / Закат / Океан) | статичные CSS-слои, пресеты в JSON |
| Своя картинка | `<input type=file>` → `FileReader` → data URL или файл в `userData/wallpapers/`; `background-size: cover` |
| Цвет темы | просто `--ym-bg` |
| Без фона | `none`, остаётся только зерно |

Важно: **вуаль обязательна**. Без затемняющего слоя панели на светлой обложке теряют контраст — в прототипе это `rgba(5,5,9,.46 → .66)` для тёмной схемы и `rgba(252,248,240,.55 → .70)` для светлой.

Анимация: `background-image` не анимируется плавно. Если нужен кроссфейд между треками — два абсолютных слоя и смена `opacity`, а не `transition: background-image`.

## 6. Производительность

`backdrop-filter` — самая дорогая вещь в макете. Правила:

- не больше 4–5 размытых поверхностей одновременно (сайдбар, шапка, плеер, карточки-оверлеи);
- на карточках blur не нужен — там достаточно полупрозрачного фона;
- при `prefers-reduced-motion` и на слабых GPU отключать blur целиком (слайдер уже есть);
- в Electron включить `backgroundThrottling: false` только если реально нужен фон-анимация, иначе оставить как есть;
- окно с `vibrancy`/`mica` на Windows 11 — альтернатива CSS-blur, но поведение зависит от версии ОС; проще оставить CSS.

---

## 7. Устойчивость к обновлениям

- Версионировать селекторы для L3: держать их в одном файле `patches.css` с комментарием «актуально для music.yandex.ru на дату X».
- Перед применением патча — `MutationObserver` и проверка: если якорных элементов нет, патч не применяется, интерфейс остаётся работоспособным.
- Никогда не полагаться на хеши классов (`class="d3f8a"`): только `role`, `data-*`, aria-атрибуты и текстовые якоря.
- Тема (L1–L2) от их релизов не зависит вовсе — это главный аргумент за нашу обёртку.

---

## 8. Что сознательно не делаем

- не подменяем аудиопоток и не обходим DRM;
- не вставляем чужой звук в их плеер;
- не патчим токены авторизации;
- не «лечим» подписку.

Импорт из Spotify/SoundCloud — только метаданные и матчинг в каталоге Яндекса, плюс легальное воспроизведение через официальные виджеты/SDK.

## 9. Этапы

| Этап | Объём | Результат |
|---|---|---|
| **MVP** | обёртка + токены + вкладка «Оформление» + 4 варианта + пресеты + экспорт/импорт | тема работает, но данные — демо |
| **v1** | авто-палитра из обложки, свои обои, применение к реальному веб-вью | «оформление» на живом приложении |
| **v2** | импорт плейлистов Spotify, вкладка SoundCloud с виджетом, синхронизация «сейчас играет» | второй источник и перенос библиотеки |
| **v3** | Spotify-плеер (Premium), RPC, горячие клавиши, трей | полный мульти-источник |

Оценка MVP по этому макету: 3–5 дней, если не изобретать заново — сетка и токены уже есть в прототипе.
